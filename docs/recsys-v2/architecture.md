## Running system

- **Shipped in-app engine:** `web/src/engine/runtime.ts` creates LocalApi; the guarded native HTTP bridge is in `native-http.ts`, `android/` and `windows/`. The user's history is in the app's local Store/IndexedDB (`store.ts`, `idb.ts`). The page routes requests through `api.ts`. The optional Python FastAPI server (`server/airwave_discovery/app.py`) powers `node start.mjs` for development, not the Android APK or Windows executable.
- **Retrieval:** `pipeline.ts` asks YTM, SoundCloud, Deezer/Apple where available, merges by conservative recording identity (`identity.ts`) and retains provenance with source IDs. Failures are per-source. Audio enrichment in `local-api.ts` now samples the head and lower provisional ranking bands instead of only the initial top 20; the same model/preprocess cache keys are preserved. No incompatible embedding spaces are mixed.
- **Ranking:** `engine.ts` remains deterministic. `rank_v2` (Settings, default true) gates the new source-family corroboration, null-vs-zero handling, correlated/seed-donated genre filtering, no-vector coverage denominator, bounded behavioral feedback, and three-horizon taste. The v1 score/select path and Python golden fixture remain available when false. Provider support is not silently upgraded by the ranking flag. The Python development server also honors the flag for evidence handling and feedback, but has no `taste2` horizon implementation; the shipped TS runtime has it.
- **Taste:** `taste2.ts` constructs long (120-day half-life), recent (10-day), and app-session views from locally stored events. The context passes it only under the v2 flag. Each horizon's vote is evidence-aware, capped at 25% of affinity; profile events with no genre/BPM do not manufacture those attributes. Behavioral completions/replays of one track/day are limited to first full + second half; later loops do not teach more. Explicit feedback remains stronger. This is a heuristic, not a trained collaborative model.
- **Playback events:** `Player.tsx` uses `ListenMeter` in `util.ts` to count positive position deltas only while playing, excluding pauses, buffering and seeks. A union of played time intervals tracks unique content coverage separately from elapsed listened time. Full completion requires substantial unique coverage (70% known full track; preview 80%) and the end event; an unknown duration needs at least 20 measured seconds but does **not** yield a ratio. Skip is user pressing Next early (2–12 seconds); errors, closure and external links do not create skips. A per-playback-instance event ID prevents callback/retry duplication. Persisted v2 metadata: `schema`, `duration`, `coverage`, `medium`, `session`, `origin`, `confidence`; main event has id, track key, kind, artist, track snapshot, listened seconds and timestamp. Python SQLite migration adds one nullable `meta` JSON column; old rows survive. TS Store fields are optional; existing data is not rewritten.
- **Import:** `import.ts` parses user-selected Spotify extended history JSON or extracted ListenBrainz JSONL; limit 2,000 newest usable events per file, explicit review/confirm, no automatic upload. Timestamps and deterministic IDs are preserved, so re-import dedupes. Spotify trackdone → completion (no known track duration inferred); only short `fwdbtn`/skipped → skip. ListenBrainz submission → lower-weight `qualified`, with null listened duration. Neither external playback nor an unknown provider failure becomes taste evidence. Import uses `/api/import/history` on LocalApi or localhost Python; both persist only locally. Apple export importer is not shipped because the available schema was not validated.
- **Selection and explanations:** original `select()` retains artist caps, seed balance, tiers, exposure penalties and diversity. `explain()` cites weighted evidence and independent provider families only if multiple counted provenance sources exist. Audio claims require a real score/vector; missing evidence remains visible.

## Data, privacy and licensing

No automatic personal-history upload. Audio analyses are on legitimately supplied previews, not scraped DRM streams. The existing DCLAP model is AGPL-3.0 and must ship with its corresponding source as the project already documents in `docs/LICENSES.md`. GPL-2.0 ListenBrainz/Troi code was **not** copied. TuneLog/implicit code was not vendored either; general scoring ideas were independently implemented. BeatFinder's README claims MIT but its clone lacked a LICENSE file; do not copy its implementation without a rights check. See `repository-review.md` for pinned upstream commits and implementation citations.

## Rollback / upgrade

In Settings, uncheck **Improved ranking (v2)** to use v1 scoring on existing local history; no migration rollback or deletion is required. The v2 rows remain readable by v1. To undo code without touching history, switch from `recsys-v2` back to `main` in the nested repository after saving any uncommitted changes. Do **not** reset the user database. Imported `qualified` events will not affect a pre-v2 binary, and a later rollback binary may not understand the new SQLite meta column but its old queries still address the original columns.

## Not implemented (do not advertise)

No Apple export parser, ListenBrainz collaborative candidate fetch, ALS/BPR training, Spotify private API history/playback, account auth, session-level hours charts, guaranteed preview-to-full-song mapping, or end-to-end device APK/Windows installer smoke in this iteration. The v2 score change is measured on frozen/synthetic pools; no human taste superiority has been established without real consented chronological history and exposure logs.
