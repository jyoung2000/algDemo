# Provider capabilities — Airwave Discovery recsys-v2

Checked 2026-11-01. This matrix separates the in-app TypeScript runtime (`web/src/engine`) from the optional Python development server (`server/airwave_discovery`). **Working** is only used where the Python `/api/health` live probe returned `working` at 2026-11-01T02:56:16Z (raw response: `D:/MusicRecommendationLab/work/health.json`), or where the live browser run produced a recommendation. Other entries are code-supported but **not live-tested here**. Network conditions can change. Search/catalog match, history import, audio analysis, and playback are distinct capabilities.

**Failure behavior:** a failed source is reported with a source status and the other sources continue. Network calls use bounded per-request budgets, timeouts and caching (`web/src/engine/net.ts`, `local-api.ts`). Provider outage is not negative taste evidence. UI explanations use actual provenance and only cite audio where a vector was present; the live browser explanation explicitly said no audio comparison for a track without a preview.

**Live caveat:** The Python browser run returned a `405` on a model-file HEAD request; this is **not** proof that DCLAP audio analyzed any track. The Android native bridge and Electron bridge were not live-smoked on devices in this run. A desktop browser `?local=1` search hit CORS in this environment; local engine unit/integration tests pass, but that browser search is not equivalent to the native bridge. An Apple preview, Spotify private history, ListenBrainz collaborative candidates, and real full-track SoundCloud telemetry must not be advertised as working.
