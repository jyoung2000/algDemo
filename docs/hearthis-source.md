# HearThis full-song source (0.10.9 / 0.7.9)

The source chain now searches HearThis after YouTube Music, YouTube videos, SoundCloud, Bandcamp and Audius, and before Internet Archive. It uses the public keyless HearThis API and exposes a candidate only when the row is explicitly public (`private === "0"`; a missing field fails closed), marked `type: "Original"`, creator-downloadable (`downloadable === "1"`), at least 60 seconds long, and declares a recognized Creative Commons or public-domain license. The candidate still has to pass the app's strict title, artist and duration recording matcher. Public streaming alone is not sufficient.

The download evidence is bound to the recording: the creator's `download_url` must be the `hearthis.app` twin of that exact track page (`<user>/<track>/download/`), optionally with an opaque `secret` token, so a permission belonging to a different upload cannot vouch for this one.

A remembered link is not standing permission (SOURCE-HEARTHIS-002). A license and the creator's download switch can both change after a hit is cached, so a cached HearThis answer is re-read from the track's own public JSON and re-gated — license, privacy, originality, downloadability and recording identity — before it reaches the downloader. Any failure (withdrawn download, changed license, unreachable API) drops the link and records a short-lived miss instead of reusing it.

That re-check has to cover every path to the downloader, not just the source chain. The persisted ready-source map (`airwave.ready-source.v1`) has no expiry, so it refuses to store or return a link on a host where the download right belongs to the uploader and can be withdrawn — `hearthis.at` today. A HearThis song that downloaded once therefore goes back through the chain on the next launch instead of being handed to yt-dlp from storage, which is what actually closes the withdrawn-permission hole.

The downloader receives only the canonical `https://hearthis.at/<user>/<track>/` page, compared against the raw link the page handed over. The two URL parsers disagree in opposite directions, so the raw comparison is what makes the three shells agree: `new URL()` silently normalizes dot segments and empty `?`/`#` delimiters, while Android's `java.net.URI` lowercases the host, keeps an explicit `:443` and decodes percent-escapes (`/a/b%2E%2E/` would become `/a/b../`). Android therefore compares against `getRawPath()` and requires an absent port. All eight rejected forms — `/a/b/../c/`, `/a/b/?`, `/a/b/#`, a missing trailing slash, an uppercase host, an explicit `:443`, and percent-encoded paths `de%65p` and `song%2E%2E` — are refused by web, Windows and Android alike. Profile pages, search pages, deceptive hosts, credentials, non-HTTPS links and query redirects are rejected too. The API's separate `download_url` is used only as evidence; the app never executes it. Search and per-track metadata requests are restricted to `api-v2.hearthis.at`, and the source is capped by the existing query budget so an unavailable song does not leave discovery spinning indefinitely.

Live verification used HearThis track ID `2153536`, a 377-second Attribution-licensed original with creator-enabled download. The real API returned the eligible row; on packaged Android 0.10.9 and Windows 0.7.9, yt-dlp downloaded it from the canonical track page (6,037,446 and 6,037,447 bytes), the native bridge reported a locally ready file, and a media element decoded the full 377.2 seconds and advanced playback. Every unsafe and non-canonical HearThis URL listed above was rejected through the native bridge of both packaged shells. That file is an unrelated downloader smoke test: it is not bundled, not delivered, and does not count toward the owner's queue.

This source does **not** establish 97/97. Live HearThis searches found no strict match for either the 219-second standalone *Plant Island* recording or Piano Cartel's 290-second *Aria Math (From "Minecraft") (Piano Cover)*. A different version, an unlicensed upload, a preview, metadata without complete audio, or a filtered 95-song denominator is not counted. Owner-kept Music remains outside discovery expiry and reset; a reset must never remove copies the owner chose to Keep in their Music folder.
