# Local queue playback architecture (November 4, 2026)

## Contract
Installed Windows/Android playback never uses an iframe as a fallback for added/discovered songs. Search previews can remain remote. The player asks for a confident full-song recording (YouTube Music match or a valid direct YouTube/SoundCloud track URL); if none exists or acquisition fails, it shows an actionable error instead of playing a 30-second preview as the song. Only fetch music the listener has the rights to access and keep; no DRM bypass.

## Data flow
1. Discover/search yields metadata and source links; `Player` resolves the best full-song URL, deduplicates in `LocalLibrary`, and calls the native downloader with `cache=true`, original audio. This retains an efficient compressed source (usually Opus) rather than transcoding it. Auto-downloads go into private app storage, not the user's permanent Music folder.
2. The native shell indexes source URL → private audio file and serves it only at the app origin at `/local-audio?u=<link>`. The WebView cannot seek reliably against its intercepted Range response, so `LocalLibrary.src()` fetches the local file once, creates a Blob URL, and passes it to one of two permanent HTMLAudioElements. The Web Audio graph connects those elements to EQ and crossfader. Keep at most three live Blob URLs (current, cued, spare), never revoking active/cued ones.
3. The first upcoming track is fetched proactively even if the mixer is off. A crossfade cues the full local song, not a preview. Every handoff obeys the play-through rule (at least 95% by default); a missing download means no blend. Skip-throughs cancel stale cache jobs on Windows.
4. Settings `cache_gb` (0.25–20 GiB, default 1) limits private queue audio only. Cache indexes persist across restarts; LRU evicts only unprotected audio and refuses a song that would exceed quota while playing/cued audio is protected. Intermediate downloads and app metadata are outside this quota. Explicit Download/Keep copies a cached song to the user-selected permanent folder and never removes the playback copy; permanent copies are intentionally outside the evictable quota. Changing folder applies to subsequent Keep/downloads, not a bulk migration of older saved songs.
5. On native acquisition failure, the player displays the error and offers an explicit retry on Play. It does not silently fall back to an iframe. For files too large to fit the quota, the listener must increase it or choose another recording.

## Platform/verification boundary
Windows prevents renderer throttling while hidden and requests a process suspension blocker only while a deck plays. Android needs a real MediaSessionService-owned player for guaranteed continuity if the Activity/WebView is destroyed while locked; an Activity-hosted WebView plus foreground service can improve lock-screen behavior but cannot guarantee process/activity recreation. Verify physical screen-off, Doze and interruptions on a real device before claiming that guarantee. The two-deck Web Audio EQ/crossfader remains in the page and requires a service-owned DSP design for full Android background lifecycle parity.

Windows tests: `node --test windows/downloads.test.cjs`; web tests: `cd web && node ../../node_modules/vitest/vitest.mjs run --root . --dir src`; production web build: `node ../../node_modules/vite/bin/vite.js build`. Android build and device playback must be tested separately.
